# LightBot 重构方案：症状根因修复 + 后端模块拆分 + 前端单循环化

## 已定位的根因（对应你列的每个症状）

| 症状 | 根因（代码位置） |
|---|---|
| 回复"(模型未返回内容)" | 思考模型 reasoning 与正文共享 max_tokens；流式调用只传 `reserve=1024`（chat.rs:994），思考一长正文必空。且流式 `finish()`（llm.rs:421）对空正文不报错，直接落占位符（chat.rs:1065） |
| 多余换行符 | 全链路只有 `trim()`（llm.rs:109/423），无空行折叠；`parse_memory_ops` 剥标记后残留空行也不清理 |
| 有时不回复 | @/引用触发但剥关键词后文本为空 → 静默 return（chat.rs:923-927）；排队超 8 条静默丢弃（chat.rs:1127） |
| 思考太长 | 无硬性上限，仅提示词软约束；轻量插话通道没关思考（light_reply chat.rs:1357 走 `chat()`，纯浪费） |
| 分不清谁说的/何时 | 历史注入只有 `[QQ123]` 前缀，**无时间戳**（ts 落了盘但没注入，chat.rs:1296-1306）；插话单轮请求连前缀格式都不同 |
| 记忆失忆/漂移 | 摘要折叠丢失游戏状态类细节；模型对同一事实反复措辞写入 → 矛盾记忆并存（去重仅全串相等）；注入格式只有 MM-DD |
| 管理页时序混乱 | 三条并行更新路径（事件轮询 500ms / 详情防抖 80ms / pollLive 固定 1.5s 全量刷）竞争写同一 DOM；`turn_delta` 是死代码（后端空实现 chat.rs:544）；`paused` 是隐式全局变量 |
| 耦合 | chat.rs 2571 行 god-module；8 张平行 HashMap 各自加锁清理；memory.rs 反向依赖 chat.rs；commands.rs 4 处复制"未运行读盘兜底"；发送侧无 CQ 转义（模型输出可注入 CQ 码，napcat.rs:156） |

## Phase 1 — 稳定性修复（小 diff，先做，每项可独立验证）

1. **思考预算挤占正文**（修"未返回内容"）
   - `llm.rs build_body`：thinking 启用时 max_tokens 用 `m.max_tokens`（不被小 reserve 卡死），disabled 时维持 `min(reserve, max)`。
   - `StreamedChat` 记录 `finish_reason`；`finish()` 改返回 `Result`：正文空时返回 Err（注明"思考耗尽/截断"+ finish_reason）。
   - `full_dialogue`：正文为空且 reasoning 非空 → 自动用"关闭思考"重试一次（非流式），成功则发送；占位符仅作最后兜底。`decide()` 的 32 上限提到 256（思考模型同样被吃光）。
2. **输出清洗**（修换行符）：新 `outbound::sanitize_reply`——trim 首尾、去行尾空白、3+ 连续换行折叠为最多一个空行、去零宽字符(U+200B/FEFF)。发送与落历史统一用清洗后文本。
3. **空触发兜底**（修不回复）：@/引用/私聊触发但文本为空 → 注入占位提问 "(对方 @ 了你，但没有说别的)" 走正常对话，不再静默丢弃；队列丢弃加 warn 日志。
4. **时间戳注入**（修谁说的/何时）：历史与当前提问前缀升级为 `[MM-DD HH:MM][QQ123] `（ts>0 时；旧记录 ts=0 优雅降级）。一次性缓存前缀成本，可接受。
5. **记忆漂移缓解**：MEMORY_GUIDE 增加"事实变化时先删旧条目再写新条目，避免矛盾记忆"；`system_text` 注入格式加 HH:MM；`summarize` 提示词明确保留"已做出的选择/决定/游戏状态"。
6. **CQ 转义**：发送前按 OneBot 11 转义 `&`/`[`/`]`，防模型输出 CQ 码被执行。
7. **分段优化**：优先在换行/段落边界切分，超长单段才字符硬切（不改 max_msg_len 语义）。
8. **杂项**：napcat.rs:617 反向端口非法 expect panic → 改错误上报；light_reply 明确禁用思考。

## Phase 2 — 后端拆分（纯结构重构，行为不变）

chat.rs 2571 行拆为（lib.rs 同步更新，e2e 测试 lib.rs:68 作为回归安全网）：
- `estimate.rs`：estimate_tokens / compute_drop（解除 memory.rs→chat.rs 反向依赖）
- `events.rs`：FrontendEvent / EventBuf / LiveTurn（删除废弃 TurnDelta 变体）
- `session.rs`：HistoryMsg / Session / session_key / 磁盘扫描与改写删函数
- `runtime.rs`：新 SessionRegistry——8 张平行 HashMap（activity/msg_count/interject_at/trail/status/aborts/pending_msgs/live）+ gates 合并为单一结构，清理原子化
- `outbound.rs`：sanitize / cq_escape / 分段 / 发送
- `context.rs`：build_messages / trim_context / fold_history / render_trail
- `botcmd.rs`：斜杠命令
- `interject.rs`：活跃度 + 采样
- `chat.rs` 瘦身为 ChatCore 编排层；commands.rs 提取"未运行读盘兜底"公共 helper

## Phase 3 — 前端单循环化（功能与外观不变）

- 单一 `tick()`（ui_refresh_ms 驱动）：拉事件 → 设各面板 dirty 标志 → 只刷 dirty 面板；详情页增量渲染并入 tick（去掉 80ms 独立防抖定时器）；每 ~8s 慢速全量对账自愈。
- 删除 pollLive 1.5s 固定轮询与 turn_delta 死路径；修复 `paused` 隐式全局；启停按钮 await 后立即拉状态（去掉 setTimeout 猜测式刷新）。

## Phase 4 — 验证与收尾

- 新增单测：sanitize / CQ 转义 / 分段边界 / 时间戳前缀 / 空触发兜底 / 空正文重试。
- `cargo test`（含 e2e）、`cargo build`、`cargo clippy` 全绿。
- README 架构章节更新为新模块图。

## 说明

- 不新增任何配置项（尊重"设置项繁杂"的抱怨）；MEMORY_GUIDE 等常量文本改动会一次性破坏缓存前缀，属预期成本。
- 分阶段提交，可逐段回退；行为变化点仅限上表所列，均直接对应你报告的症状。
