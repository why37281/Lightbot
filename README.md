# 💡 LightBot — 轻量级 NapCat QQ AI 机器人框架

基于 **NapCat(OneBot 11)+ AI 大模型(DeepSeek 等)** 的 QQ 机器人框架,主打:

- **极致轻量**:Tauri v2 + Rust 后端 + 原生 Web 前端,单个可执行文件(几 MB),内存占用远低于 Electron 方案;
- **上下文缓存优化**:专为 DeepSeek 自动 context caching 设计 —— 人设前缀固定、历史只追加、截断只删头部,持续保持高缓存命中率(命中部分计费约为正常的 **1/50**);
- **思考模式**:适配 DeepSeek V4(deepseek-v4-flash / deepseek-v4-pro),支持 thinking 开关与推理强度(low/high/max),思考模式下自动省略不生效的 temperature 参数;
- **高度可自定义**:多模型切换、多套人设、触发规则、上下文预算、摘要折叠等全在 GUI 里完成,**基本不需要手改配置文件**;
- **全事件支持**:消息 / 全部通知类型(加群、退群、禁言、撤回、戳一戳、红包、签到等 NapCat 扩展)/ 加好友加群请求 / 心跳,未知类型原样透传,一个不丢;
- **跨平台**:Windows(优先,系统自带 WebView2)/ Linux / macOS。

## 快速开始

### 1. 准备 NapCat

1. 安装 [NapCat](https://napcat.napneko.icu/)(Windows 直接解压运行,登录 QQ 后即为运行态);
2. 打开 NapCat 的 WebUI(`http://127.0.0.1:6099`),进入「网络配置」:
   - **正向 WS(推荐)**:新建一个 `WebSocket 服务器`,端口保持默认 `3001`(NapCat 作为服务端监听,LightBot 作为客户端主动连接它);
   - **反向 WS**:新建 `WebSocket 客户端`,地址填 `ws://127.0.0.1:3005`(NapCat 作为客户端主动连 LightBot 的监听端口);
   - 如需鉴权,两侧填写相同的 `access_token`(LightBot 通过 URL 参数传递,与 NapCat 兼容)。
3. 保持 NapCat 运行。

### 2. 运行 LightBot

- **Windows**:直接运行 `lightbot.exe`(发布产物)。
- **开发运行**:安装 Rust 工具链后 `cargo run`。

| 连接设置 | 正向/反向模式、WS 地址、端口、token、机器人 QQ(留空自动获取)、触发方式、分段长度 |
| 模型设置 | 多模型管理(DeepSeek V4 / OpenAI / 通义 / Kimi / Ollama 均可,OpenAI 兼容)、思考模式与推理强度、温度、max_tokens、**每模型单价(命中/未命中/输出)**、测试连通 |
| 会话设置 | 上下文预算、摘要折叠、群/私聊开关、**回复决策器**、空闲清理、**主动插话(概率/冷却/软 at/钩子词)**、**长期记忆管理(双方案位置策略 + 自动控制)**、**消息忽略**、**钱包余额**、会话列表(带状态胶囊,可点开详情页)与清空 |

### 5. 主动插话(活人感)

除了被 @ / 回复 / 关键词触发,**LightBot 还会像活人一样偶尔在群里接话**:

- **软 at**:消息中提到机器人称呼(如"小灯你怎么看")→ 完整通道必回,记入历史;
- **插话采样**:概率 = 基线(默认 5%)+ 钩子词加分(怎么/为什么/帮…)− 纯水减分(单字/表情/复读),再按群活跃度做**钟形曲线缩放**(有人聊且节奏不快时参与感最强 ×1.6,冷场 ×0.1~0.4 避免自言自语,刷屏 ×0.5 避免被淹没);
- **固定频率模式**:另可选每 N 条群消息插话一次(默认 5),不做概率采样,冷却期满即触发;
- **轻量通道**:插话单轮、小上下文(≤120 tokens 输出)、**不落盘、不占会话上下文、不新开会话**,预算完全无感;开启「完整上下文」开关后,插话改为**完整通道**(与普通回复一致:历史/记忆/轨迹按设置注入,并记入历史);
- 所有主动发言(软 at + 插话)共用**冷却**(默认:距上次主动发言 25 条新消息;固定频率模式按每 N 条),防骚扰;
- **活跃度窗口**(默认 2 分钟)可调:衡量"当下氛围"用短窗口(响应快),衡量"长期热闹程度"用长窗口(更稳)。

### 6. 回复决策器(可选,默认关闭)

在「会话设置」中开启后,**任何触发(@ / 软 at / 插话采样)命中,都会先让当前模型判断这条消息是否需要回复**,模型认为不需要则静默跳过:

- 决策请求开销极小:32 tokens 输出上限;**先思考再输出字母**,思考模式与推理强度跟随模型配置(与正式回复一致),思考内容同样显示在会话详情页;
- 决策上下文只带人设 + 当前消息(附**触发说明**:@你/引用回复/私聊/关键词/称呼/插话采样),不带历史——模型知道这条消息是怎么触发的,不会把 @ 消息误判为无关闲聊;
- 决策失败/乱输出时**保守回复**(不会漏回消息);插话被决策拒绝时同样消耗本次插话机会(防高频重试);
- 所有思考(决策器与正式回复)的注入上下文都要求**思考简短:想清楚接下来回什么即可**。

适合希望机器人"更克制"的场景——比如群聊里 @ 泛滥时,让模型自己过滤掉没必要回的。

### 7. 长期记忆(默认开启)与记忆位置策略

模型和用户都可以读写记忆:

- **模型自动写入**:对话中了解到值得长期记住的信息(用户偏好、重要事实、约定)时,在回复末尾附 `[记忆:添加 xxx]` 标记,后端解析并执行、剥离标记后发送,零额外调用;
- **用户管理**:QQ 命令 `/remember <内容>` 添加、`/forget <内容或序号>` 删除、`/memories` 查看;GUI「会话设置 → 长期记忆」可浏览/添加/删除;
- **作用域**:按群/私聊独立(`sessions/memories/{key}.jsonl`);记忆有 token 上限(默认 1200),超出删最旧。

#### 记忆放在哪里?两个方案(缓存命中率的权衡)

DeepSeek 的前缀缓存按「从头开始的最长公共前缀」计费,命中价约为未命中的 **1/50(flash)~1/120(pro)**。记忆注入位置直接决定它吃命中价还是未命中价:

| | 方案一(默认记少/变化频繁) | 方案二(记忆多且稳定) |
|---|---|---|
| 消息流 | `人设 → 摘要 → 历史 → 记忆 → 提问` | `人设 → 摘要 → 记忆 → 新历史 → 提问` |
| 记忆每轮计费 | **未命中价**(历史每轮在增长,记忆位置跟着漂移,前缀总在记忆前断开) | **命中价**(位置稳定) |
| 代价 | 无 | 记忆变更一轮 `记忆+新历史` 全 miss;新历史超过阈值折叠摘要时再断一次前缀 + 摘要调用本身费用 |
| 适合 | 记忆少(几百 token 内)、每轮都在改 | 记忆多(数千 token)、几天才改一次 |

**阈值怎么定(方案二「新历史积累到多长才折叠」):**
设每轮历史净增长 `g`、记忆每轮变更概率 `p`、命中/未命中价比 `r≈1/50~1/120`。
方案二的折叠周期 = `(新历史阈值 − 保留条数的 token)/ g`,折叠会付一次 `新历史+记忆+摘要` 的全 miss 加一次摘要 LLM 调用。令「每轮摊销折叠成本 + 记忆变更成本」与「方案一记忆每轮 miss 成本」相等,可解出分界:
`记忆 token > (p×新历史 + q×折叠成本)/(1 − p − r)`(q = g / 折叠周期)。
取典型值 g≈250、p≈0.2、flash 价格、保留 10 条(约 1200 token):分界记忆量 ≈ **1500~2500 token**;而「新历史阈值」取 2500~4000 比较均衡——太小折叠太频繁,太大则记忆变更与折叠时的 miss 面积都变大。因此默认:**折叠阈值 3000 token、保留最近 10 条**(均可在 GUI 调整)。

#### 自动控制(默认开启)

开启「自动控制」后,程序按**你在模型设置里填的真实价格**与**实测指标**(记忆大小、变更频率、每轮增长)持续评估两方案:

- 每 5 轮对话评估一次,**连续 4 次结论一致**、相对节省 ≥15% 且展望 120 轮的净收益大于一次性切换成本时,才弹出**醒目审批弹窗**;
- 你点「同意」才真正切换(切换后自动重启生效);「拒绝」或切换后进入**冷却期(默认 2 小时,可在 GUI 会话设置中调整)**,不会在分界线附近来回横跳;
- 关闭自动控制后,可在 GUI 手动选择方案。

> 价格随 DeepSeek 官方调价波动(官方定价页:https://api-docs.deepseek.com/zh-cn/quick_start/pricing/ ),请在「模型设置」每个模型卡片里填当前真实单价。内置默认:V4-Flash 命中 0.02 / 未命中 1 / 输出 2 元每百万 token;V4-Pro 命中 0.025 / 未命中 3 / 输出 6。

### 8. 消息忽略(可配置前缀,入口拦截)

QQ 消息以**配置的前缀**(默认 `*`,可改,支持逗号分隔多个)开头时,机器人**完全不处理**:不回复、不触发、不入历史、不占上下文,只在日志与「会话详情页」留痕。拦截发生在**消息入口**:引用占位符会被先剥掉再判断,因此引用消息、关键词触发的消息同样被挡。群友可以自由用 `*xxx` 闲聊而不被打扰。可在「会话设置 → 消息忽略」关闭或调整前缀。

### 9. 会话详情页(白盒工作流面板)

「会话设置 → 会话列表」每一行都可点开,打开该会话的**时间线详情页**:

- 垂直瀑布流卡片:收到的消息(含触发方式)、决策器结论、思考过程(可折叠)、模型输出与最终回复、摘要折叠、错误;
- **流式直播**:QQ 侧虽然一次性回复,详情页里思考/回复是逐 token 流式滚动的,并显示每个会话的实时状态胶囊(空闲/回复中/思考中/决策中/执行中/审批中);
- **编辑/删除**聊天记录(同步改写模型上下文;对缓存命中的影响由用户自行权衡);
- **停止键**:随时中止正在进行的回复;
- 全量持久化于 `sessions/traces/{key}.jsonl`,重启后仍可回看。

### 10. 今日开销面板与余额查询

总览页实时展示今天消耗的 token 数、缓存命中/未命中构成、按类别(对话/决策器/摘要/插话)的堆叠条形图、今日费用与钱包剩余(钱包余额在「会话设置」填写,或点「查询 DeepSeek 余额」通过官方 `GET /user/balance` 接口自动填入)。用量按天落盘于 `usage/YYYY-MM-DD.jsonl`,并记录调用当时的价格快照——之后改价不会改写历史费用。

### 11. 群聊轨迹的注入行为

「会话设置 → 群聊轨迹」新增**上下文注入行为**三档:

- **窗口注入(默认)**:所有完整对话都注入轨迹,内容按「轨迹窗口 / 最多条数 / token 上限」过滤;
- **全部注入**:无论有没有 @/引用都注入,且**不设任何上限**——时间窗口、条数与 token 上限全部失效(缓冲保留 24 小时,整段缓冲全部注入;超大缓冲可能超出模型上下文窗口,请自行权衡);
- **不额外注入**:仅当消息 @ 或引用机器人才注入轨迹(关键词/软 at 触发时不额外消耗 token,条数与 token 上限仍作安全上限)。

只有「窗口注入」模式激活时间窗口设置项。

### 12. 历史消息的说话人标记

- 历史文件(`sessions/{key}.jsonl`)每条消息都带 `role`(`user` / `assistant`)与发送者 QQ,注入上下文时用户消息带 `[QQxxx]` 前缀——模型能分清**谁**说了什么;
- @ 检测只匹配 @ 机器人(或 @全体);@ 别人时保留 `@QQxxx` 目标文本;引用检测只匹配**引用机器人消息**的回复(引用别人保留 `[引用QQxxx]`),不再误触发;
- 会话详情页时间线用「👤 用户消息 / 🤖 AI 回复」显式标注每一张卡片;
- **摘要折叠保留归属**:无论方案二的新历史折叠还是超预算的旧历史折叠,生成摘要的提示词都要求每条要点标注「用户:」/「AI:」——折叠后仍然知道哪句话是谁说的。

## 缓存优化说明(DeepSeek 用户重点)

DeepSeek 的 context caching 自动生效:**请求前缀与上次一致的部分按约 1/50~1/120 价格计费**(V4 系列:命中输入 0.02~0.025 元/M,未命中输入 1~3 元/M)。缓存按「前缀单元」完整匹配,LightBot 为此做了四点设计:

1. **稳定前缀**:人设(system)永远在第一位,之后是摘要(如有),再是历史消息 —— 三者都不因新消息到来而改写;
2. **头部截断**:上下文超出预算时,只丢弃最旧消息,剩余消息逐字节不变 → 前缀哈希持续命中;
3. **摘要折叠**:需要大量丢弃时,先用 LLM 把旧消息压缩成一段固定摘要,插入前缀区,之后继续追加(可选,默认开启);
4. **会话持久化**:历史存为 JSONL,重启后同一会话继续追加,缓存跨重启延续。

在「总览」面板可实时看到每次调用的**缓存命中 token 数与命中率**、思维链 token 数、累计统计与**今日开销**(按类别的条形图)。

> DeepSeek V4 说明:思考模式默认开启(通过 `thinking` 参数控制,可在 GUI 每个模型的「思考模式」下拉中调整);思考模式下 `temperature` 等参数不生效,LightBot 会自动不发送;思维链内容通过 `reasoning_content` 返回并单独展示,多轮对话无需回传(官方推荐做法)。完整回复走流式(SSE),思考提示计时以首 token 为界,支持随时停止。

## 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 桌面壳 | Tauri v2 + 系统 WebView2/WebKitGTK | 产物几 MB,内存占用低,跨平台 |
| 后端 | Rust(tokio / tokio-tungstenite / reqwest) | 长连接天然适合,开销极小 |

## 常见问题

- **连接不上 NapCat**:先点「连接设置 → 测试连接」;确认 NapCat 网络配置里 WebSocket 服务已开启、端口一致、access_token 一致。
- **群里不回复**:检查触发方式(默认 @机器人 或回复引用或关键词);确认「启用群聊」勾选;机器人 QQ 号会自动获取,若未获取到请手动填写。
- **回复超长**:自动按「单条消息最大字符数」分段发送,可调。
- **at 检测不准确**:务必让「机器人 QQ 号」字段生效(留空会自动获取,失败则手动填写)。
