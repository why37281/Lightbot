# 💡 LightBot — 轻量级 NapCat QQ AI 机器人框架

基于 **NapCat(OneBot 11)+ AI 大模型(DeepSeek 等)** 的 QQ 机器人框架,主打:

- **极致轻量**:Tauri v2 + Rust 后端 + 原生 Web 前端,单个可执行文件(几 MB),内存占用远低于 Electron 方案;
- **上下文缓存优化**:专为 DeepSeek 自动 context caching 设计 —— 人设前缀固定、历史只追加、截断只删头部,持续保持高缓存命中率(命中部分计费约为正常的 **1/50**);
- **思考模式**:适配 DeepSeek V4(deepseek-v4-flash / deepseek-v4-pro),支持 thinking 开关与推理强度(low/high/max),思考模式下自动省略不生效的 temperature 参数;
- **高度可自定义**:多模型切换、多套人设、触发规则、上下文预算、摘要折叠等全在 GUI 里完成,**基本不需要手改配置文件**;
- **全事件支持**:消息 / 全部通知类型(加群、退群、禁言、撤回、戳一戳、红包、签到等 NapCat 扩展)/ 加好友加群请求 / 心跳,未知类型原样透传,一个不丢;
- **跨平台**:Windows(优先,系统自带 WebView2)/ Linux / macOS。

## 快速开始

### 1. 准备 NapCat

1. 安装 [NapCat](https://napcat.napneko.icu/)(Windows 直接解压运行,登录 QQ 后即为运行态);
2. 打开 NapCat 的 WebUI(`http://127.0.0.1:6099`),进入「网络配置」:
   - **正向 WS(推荐)**:新建一个 `WebSocket 客户端`,监听端口保持默认 `3001`;
   - **反向 WS**:新建 `WebSocket 服务端`,地址填 `ws://127.0.0.1:3005`(LightBot 默认反向端口);
   - 如需鉴权,两侧填写相同的 `access_token`。
3. 保持 NapCat 运行。

### 2. 运行 LightBot

- **Windows**:直接运行 `lightbot.exe`(发布产物)。
- **开发运行**:安装 Rust 工具链后 `cargo run`。

### 3. GUI 配置(核心操作都在这里)

| 面板 | 内容 |
|------|------|
| 总览 | 运行状态、连接状态、模型信息、**缓存命中率统计**、最近调用耗时 |
| 连接设置 | 正向/反向模式、WS 地址、端口、token、机器人 QQ(留空自动获取)、触发方式、分段长度 |
| 模型设置 | 多模型管理(DeepSeek V4 / OpenAI / 通义 / Kimi / Ollama 均可,OpenAI 兼容)、思考模式与推理强度、温度、max_tokens、测试连通 |
| 会话设置 | 上下文预算、摘要折叠、群/私聊开关、**回复决策器**、空闲清理、**主动插话(概率/冷却/软 at/钩子词)**、**长期记忆管理**、会话列表与清空 |
| 人设管理 | 多套 system prompt,一键切换 |
| 日志与通知 | 全部日志 + 全部 NapCat 通知实时展示 |

填好 **API Key** → 点「测试」确认连通 → 点「启动」→ 在 QQ 里 @机器人 开聊。

### 4. QQ 内命令

| 命令 | 作用 |
|------|------|
| `/clear` | 清空当前会话上下文 |
| `/stats` | 查看当前会话统计(条数 / tokens / 是否含摘要) |
| `/model <名称>` | 切换模型(需在 GUI 模型列表中已配置) |
| `/prompt <id>` | 切换人设 |

### 5. 主动插话(活人感)

除了被 @ / 回复 / 关键词触发,**LightBot 还会像活人一样偶尔在群里接话**:

- **软 at**:消息中提到机器人称呼(如"小灯你怎么看")→ 完整通道必回,记入历史;
- **插话采样**:概率 = 基线(默认 5%)+ 钩子词加分(怎么/为什么/帮…)− 纯水减分(单字/表情/复读),再按群活跃度做**钟形曲线缩放**(有人聊且节奏不快时参与感最强 ×1.6,冷场 ×0.1~0.4 避免自言自语,刷屏 ×0.5 避免被淹没);
- **轻量通道**:插话单轮、小上下文(≤120 tokens 输出)、**不落盘、不占会话上下文、不新开会话**,预算完全无感;
- 所有主动发言(软 at + 插话)共用**冷却时间**(默认 15 分钟),防骚扰;
- **活跃度窗口**(默认 2 分钟)可调:衡量"当下氛围"用短窗口(响应快),衡量"长期热闹程度"用长窗口(更稳)。

### 6. 回复决策器(可选,默认关闭)

在「会话设置」中开启后,**任何触发(@ / 软 at / 插话采样)命中,都会先让当前模型判断这条消息是否需要回复**,模型认为不需要则静默跳过:

- 决策请求开销极小:非思考模式、16 tokens 输出上限,成本接近一次连通性测试;
- 决策上下文只带人设 + 当前消息,不带历史;
- 决策失败/乱输出时**保守回复**(不会漏回消息);插话被决策拒绝时同样消耗本次插话机会(防高频重试)。

适合希望机器人"更克制"的场景——比如群聊里 @ 泛滥时,让模型自己过滤掉没必要回的。

### 7. 长期记忆(默认开启)

模型和用户都可以读写记忆:

- **模型自动写入**:对话中了解到值得长期记住的信息(用户偏好、重要事实、约定)时,在回复末尾附 `[记忆:添加 xxx]` 标记,后端解析并执行、剥离标记后发送,零额外调用;
- **用户管理**:QQ 命令 `/remember <内容>` 添加、`/forget <内容或序号>` 删除、`/memories` 查看;GUI「会话设置 → 长期记忆」可浏览/添加/删除;
- **作用域**:按群/私聊独立(`sessions/memories/{key}.jsonl`);
- **缓存友好设计**:记忆管理说明是**恒定的独立 system 消息**(开关切换不改变消息流前缀,缓存不受影响);记忆内容消息**位于历史之后、提问之前** —— 新增记忆只在末尾追加,人设/摘要/历史的前缀缓存几乎全部保持命中(只有新条目和提问本身断缓存);记忆有 token 上限(默认 1200),超出删最旧。记忆本身零额外 LLM 调用,仅 prompt 增加几行。
- **开关语义**:关闭记忆系统后,记忆内容不再发送、模型标记不再执行(但仍会被剥离,不会泄漏到群里),消息流前缀与开启时完全一致。

### 8. QQ 内命令汇总

| 命令 | 作用 |
|------|------|
| `/clear` | 清空当前会话上下文 |
| `/stats` | 查看当前会话统计(条数 / tokens / 是否含摘要) |
| `/model <名称>` | 切换模型 |
| `/prompt <id>` | 切换人设 |

## 缓存优化说明(DeepSeek 用户重点)

DeepSeek 的 context caching 自动生效:**请求前缀与上次一致的部分按约 1/50 价格计费**(V4 系列:缓存命中 0.02~0.025 元/M,未命中 1~3 元/M)。缓存按「前缀单元」完整匹配,LightBot 为此做了四点设计:

1. **稳定前缀**:人设(system)永远在第一位,之后是摘要(如有),再是历史消息 —— 三者都不因新消息到来而改写;
2. **头部截断**:上下文超出预算时,只丢弃最旧消息,剩余消息逐字节不变 → 前缀哈希持续命中;
3. **摘要折叠**:需要大量丢弃时,先用 LLM 把旧消息压缩成一段固定摘要,插入前缀区,之后继续追加(可选,默认开启);
4. **会话持久化**:历史存为 JSONL,重启后同一会话继续追加,缓存跨重启延续。

在「总览」面板可实时看到每次调用的**缓存命中 token 数与命中率**、思维链 token 数,以及累计统计。

> DeepSeek V4 说明:思考模式默认开启(通过 `thinking` 参数控制,可在 GUI 每个模型的「思考模式」下拉中调整);思考模式下 `temperature` 等参数不生效,LightBot 会自动不发送;思维链内容通过 `reasoning_content` 返回并单独展示,多轮对话无需回传(官方推荐做法)。

## 配置文件(一般不需要手动编辑)

- Windows:`%APPDATA%\com.lightbot.app\config.json`
- Linux:`~/.config/com.lightbot.app/config.json`

GUI 的「保存配置」会全量写入。手改后需重启程序生效。会话历史存于同目录 `sessions/*.jsonl`。

## 跨平台构建

```bash
# Windows(MSVC 工具链 + Rust stable)
cargo build --release          # 产物: target/release/lightbot.exe

# Linux(需系统依赖)
sudo apt install libwebkit2gtk-4.1-dev libssl-dev build-essential
cargo build --release
```

> 说明:Linux 构建需 OpenSSL 开发库(HTTP 客户端走 native-tls);Windows 使用系统 Schannel,无额外依赖。

## 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 桌面壳 | Tauri v2 + 系统 WebView2/WebKitGTK | 产物几 MB,内存占用低,跨平台 |
| 后端 | Rust(tokio / tokio-tungstenite / reqwest) | 长连接天然适合,开销极小 |
| 前端 | 原生 HTML/CSS/JS(零构建) | 无 node_modules,静态资源打进二进制 |
| 存储 | JSON(配置)+ JSONL(会话) | 无需数据库,可读可备份 |

## 常见问题

- **连接不上 NapCat**:先点「连接设置 → 测试连接」;确认 NapCat 网络配置里 WebSocket 服务已开启、端口一致、access_token 一致。
- **群里不回复**:检查触发方式(默认 @机器人 或回复引用或关键词);确认「启用群聊」勾选;机器人 QQ 号会自动获取,若未获取到请手动填写。
- **回复超长**:自动按「单条消息最大字符数」分段发送,可调。
- **at 检测不准确**:务必让「机器人 QQ 号」字段生效(留空会自动获取,失败则手动填写)。
